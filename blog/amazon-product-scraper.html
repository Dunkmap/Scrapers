Quick answer

Amazon Product Scraper turns any Amazon search, category or product URL into full product records with 55 fields: price and list price, ASIN, stars and star breakdown, bestseller ranks, sellers, variants, images and delivery dates. It works on 24 Amazon marketplaces with no login and no Amazon API key. Full records cost $4.50 per 1,000; with details switched off, the search-grid fields cost $0.50 per 1,000. Error rows are never charged.

Limits worth knowing

  • Offers cost extra. The featured (buy box) offer is included. Other sellers come from the offers panel, which you switch on with maxOffers and which is charged separately.
  • Review insights, not every review. You get the star breakdown and Amazon's AI review summary, not each review's text.
  • Amazon caps some searches at 7 pages. Use a category URL, or a category plus a search term, to go deeper.
  • Prices follow the delivery address. Two runs from different locations can show different prices, so set a postcode when you compare.

Frequently asked questions

Is there an Amazon product API I can use without a key?

The official Amazon Product Advertising API needs an approved affiliate account and a key. Amazon Product Scraper reads the public product pages instead, so it needs no key, no login and no cookies, and it returns fields the official API does not, such as bestseller ranks, the AI review summary and seller business details.

How much does it cost to scrape 1,000 Amazon products?

$4.50 for 1,000 full product records with all 55 fields, plus $0.00005 per run. With product details switched off you get the search-grid fields for $0.50 per 1,000. Error rows are never charged.

Which Amazon marketplaces does it support?

24: amazon.com, .co.uk, .de, .fr, .it, .es, .nl, .se, .pl, .com.be, .ie, .com.tr, .ae, .sa, .eg, .in, .sg, .co.jp, .com.au, .ca, .com.mx, .com.br, .cl and .co.za. Each returns its own language, currency and delivery dates.

Can I scrape Amazon products with Python?

Yes. Start a run with the apify-client package and read the results as JSON, as shown above. JavaScript and plain HTTP work the same way.

Can it scrape a whole Amazon category?

Yes. Paste the category URL and raise the result limit. Amazon caps some bare search terms at 7 pages; a category URL, or a category combined with a search term, goes deeper.

Can I get prices for a specific postcode?

Yes. Set a ZIP or postal code and the prices, stock and delivery dates are the ones that address sees, at no extra charge.

Does it scrape Amazon reviews?

It returns review insights: the star breakdown, review count and Amazon's own AI review summary with sentiment per aspect and the quoted reviews behind it. Review-by-review scraping is not included.

Is scraping Amazon product data legal?

Open the Actor on Apify

Step 1 — Run a small test

  1. Open the Actor on Apify and sign in. The free plan has enough credit to try it.
  2. In Enter one or more Amazon category or product URLs, paste one URL. The field starts with https://www.amazon.com/s?k=keyboard as an example.
  3. Set Max results (per start URL) to 25 for the first run, not the default 100.
  4. Click Start, then watch the Output tab.

Check a row or two before you spend more. A full record carries about 55 fields, so it is easier to see what you are paying for on 25 products than on 1,000.

Step 2 — Pick the right URL

Three kinds of Amazon URL work, and the one you choose decides how much you get back:

URL typeExampleWhat you get
Searchhttps://www.amazon.com/s?k=keyboardEvery product on the result pages
Categoryhttps://www.amazon.com/s?i=electronics&rh=n%3A16225007011Everything in the category, past the search cap
Producthttps://www.amazon.com/dp/B09X7MPX8LThat one product

The domain decides the marketplace: an amazon.de URL returns German listings in euros, with no proxy setting needed. All 24 marketplaces work this way.

Amazon caps plain searches at about 7 pages. To go deeper, use a category URL, or a category combined with a search term — rather than searching for diamond rings, open the Women’s rings category and search inside it.

Step 4 — Set the delivery location

Amazon shows different prices, stock and delivery dates depending on where it is shipping. Two runs from different locations can disagree, so pin the location when you compare prices over time.

  • Zip code and Country code set the delivery address. There is no extra charge for this.
  • Location deliverable routes decides where the address is applied — product pages, search pages, offers, or any combination. Narrowing it speeds up a run when you only need localised data in one place.
  • Language asks Amazon for a specific language. Each domain supports its own set; an unsupported choice falls back to the domain default.
  • Proxy country defaults to matching the marketplace, which is usually what you want. Change it only to see what a shopper in another country sees.

Run it from Python or the API

Install the client with pip install apify-client, then start a run and read the products. Replace YOUR_APIFY_TOKEN with the token from your Apify account settings.

from apify_client import ApifyClient

client = ApifyClient("YOUR_APIFY_TOKEN")
run = client.actor("molded_mountainpass/amazon-product-scraper").call(run_input={
    "categoryOrProductUrls": [
        {"url": "https://www.amazon.com/s?k=mechanical+keyboard"},
        {"url": "https://www.amazon.de/dp/B0D14N2QZF"},
    ],
    "maxItemsPerStartUrl": 50,
    "zipCode": "10001",
    "scrapeSellers": True,
})

for product in client.dataset(run["defaultDatasetId"]).iterate_items():
    print(product["asin"], product["price"], product["title"])

The same input works from JavaScript, from a plain HTTP call to the Apify API, and from n8n, Make or Zapier without code. To keep a price history, save the run as a task and give it a schedule.

If a run returns too little

  • A search stopped early. Amazon caps some searches at about 7 pages. Use a category URL instead, or a category plus a search term.
  • Rows are missing fields. The schema is stable across marketplaces and writes an explicit null where Amazon does not show a field, so a null means Amazon had nothing there, not that the run failed.
  • Results look blocked. Requests start on datacenter proxies and retry on residential ones; amazon.in, amazon.fr and amazon.sg go straight to residential. Setting Proxy configuration to RESIDENTIAL sends every request that way: more reliable, several times the cost.
  • Captcha solver is a trade-off. It works well on .com, but even there Amazon hides attributes, manufacturer attributes and bestseller ranks after a captcha is solved. Leave it off if you need those fields.
  • Prices differ between runs. That is the delivery address, not a bug. Set a zip code and keep it fixed.
